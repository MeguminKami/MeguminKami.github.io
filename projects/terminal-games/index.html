Overview

These games were created as early programming exercises. They are small, direct, and intentionally terminal-focused: maps are represented with characters, the player moves one turn at a time, game state is recalculated after each input, and the screen is cleared and redrawn to create the feeling of a live console game.

Technical Stack

C C++

Learning C and C++ Through Games

These games were my way of making basic C and C++ programming concepts easier to understand. Instead of only writing isolated exercises, I used small terminal games to practice variables, arrays, loops, conditions, functions, structs, classes, headers, and source files in a context where every line of code changed something visible on screen.

Why Games

A terminal game gives immediate feedback. A wrong condition, coordinate, or loop does not stay abstract: the hero moves incorrectly, a wall can be crossed, or the win condition never triggers.

C++ Basics Practiced

The code practices basic C++ structure: separating logic into functions, grouping data into structs and classes, passing objects into methods, and using arrays or vectors to represent a game world.

Progression

The first versions are closer to procedural C-style code. Later versions introduce headers, namespaces, classes, entity objects, inventory flags, enemy movement, and a cleaner split between terminal rendering and game logic.

Source Code Architecture

The original projects are built like small console applications. There is no graphics engine: the code owns the map, reads keyboard input, updates the game state, clears the terminal, and prints the next frame as text.

Implementation Methods

The code is small, but it uses several real programming-project ideas: a shared input layer, separated header/source files, named game objects, validation methods, randomized placement, and a repeatable update loop.

Map Representation

Each game stores the world as a two-dimensional char array. Walls are X, the hero is H, dragons are D, the key is K, the sword is S, and the exit is E.

Example: char map[10][10]

Coordinates

Positions are stored with a small coordinate structure containing row and column values. Movement is handled by adding direction offsets to the current position.

Example: coordenadas { int i; int j; }

Movement Validation

Before a move is accepted, the code checks map bounds, walls, locked exits, and whether the next cell contains an item or enemy.

Methods: moveHeroDir(), can_exit()

Game-State Rules

Rule functions compare positions and distances. They decide if the hero collected an item, got too close to a dragon, killed a dragon with the sword, or reached the exit.

Methods: updateGame(), game_state_update()

Enemy Turns

In the later games, each dragon calculates valid neighboring cells and picks a random move. This creates a simple turn-based enemy system without needing pathfinding.

Methods: checkValidMoves(), moveDragon()

Terminal Runtime

The shared terminal header hides the platform differences between Windows and POSIX terminals, including key reads, screen clearing, cursor hiding, and short sleeps.

File: shared/terminal_input.hpp

Source File Breakdown

The source files linked inside each playable game card show the original implementation. This breakdown explains what each file contributes to the collection.

Here Be Dragons

herebedragons.cpp

The most procedural version. It uses a fixed maze, a coordinate struct, helper functions for distance and exit placement, one stationary dragon, one key, and one locked exit.

Dragon's Bane

dragonsbane.hpp + dragonsbane.cpp

Introduces a clearer split between declarations and implementation. The header defines the game objects, while the source file implements setup, rendering, movement, inventory, dragon placement, dragon movement, and win/loss rules.

Torment

ToD.hpp + ToD.cpp

Expands the same idea into a larger generated map. It adds constants for map size and dragon limits, wall generation, inventory display, many enemies, and a larger terminal rendering problem.

Shared Input Layer

terminal_input.hpp

Abstracts platform-specific terminal work. On Windows it uses console and keyboard APIs; on POSIX systems it uses terminal flags, non-blocking reads, ANSI escape sequences, and sleep helpers.

Worlds Colide

wc.cpp + wc.hpp

Currently a prototype shell with start and end screens. It is shown as source-only because it demonstrates terminal screen flow, but does not yet contain enough gameplay logic to port as a full browser-playable game.
