Batalha Naval RPG

A desktop Qt/C++ game that turns classic Battleship into a tactical RPG. It combines ship placement and hit detection with character classes, skills, action points, cooldowns, audio, a CPU opponent, and lightweight TCP online play.

Overview

Batalha Naval RPG is built as a Qt Widgets desktop application. The game keeps the familiar 12 x 12 naval grid, then adds RPG-style commanders, skill areas, cooldowns, passives, action-point decisions, themed resources, and two match paths: offline play against a CPU and online host/join play through a simple relay server.

Project Story

The project focuses on keeping Battleship readable while adding enough RPG systems to make every turn more tactical than a single coordinate guess.

Problem

Classic Battleship is easy to understand, but its turn structure can become repetitive. A richer version needs more decisions without losing the certainty of grid-based hits, misses, ship destruction, and victory checks.

Design Goal

Keep the board deterministic and readable, then layer character identity over it: different skills, passives, action costs, cooldown pressure, area previews, and audio feedback tied to each mode and commander.

Solution

A central MainWindow coordinates stacked pages, placement, turns, audio, CPU signals, and network packets while the game domain owns boards, players, ships, characters, skills, previews, and hit-response logic.

Source Architecture

The implementation is organized around four practical layers. UI state lives in MainWindow, game rules live under src/game, audio and networking are service wrappers, and all visual, font, and sound assets are embedded through Qt resources.

UI

Presentation

MainWindow, stacked widgets, character selection, placement screens, turn screens, options, victory, and defeat flow.

GM

Game Domain

board, objects, player, cpu, character, skill, and preview.

SV

Services

Sounds wraps Qt Multimedia. Client and Server wrap Qt TCP sockets and relay packets.

QRC

Resources

Images, fonts, and sounds stay behind stable runtime paths such as :/resources, :/fonts, and qrc:/sounds.

CM

Build System

CMake enables AUTOUIC, AUTOMOC, and AUTORCC, then links Widgets, Multimedia, and Network.

PS

Windows Helpers

PowerShell scripts provide the preferred build, run, and packaged-run commands for the Windows Qt MinGW setup.

Gameplay Flow

Offline mode connects player and cpu with Qt signals. Online mode uses the same turn concepts, but sends compact packet codes through a relay server instead of direct local calls.

1

Choose Mode

Create, join, or start offline against the CPU.

2

Select Character

Load commander skills, passive, preview image, and theme.

3

Place Ships

Drag, rotate, snap, validate, then mark placement ready.

4

Resolve Turns

Select a skill, preview its AOE, spend AP, and process hits.

5

Check Outcome

Ask destroy and victory responses until one player loses.

Online Multiplayer Protocol

The server is intentionally small: it accepts two sockets and relays bytes. It does not own game rules, validate attacks, or act as an authoritative match server. The clients and UI interpret packet codes and payloads.

H

Host Flow

Host starts the relay server, receives a share code, connects as client 1, and waits for the second socket.

J

Join Flow

Joiner decodes the share code, connects as client 2, then exchanges player info and ready states.

P

Packets

Single-character packet prefixes cover player info, placement readiness, hits, destroys, victory checks, turn passing, and radar.

Packet Group Codes Purpose
Setup INFO_P, R_P, PLACE_R Exchange player info, move into placement, and signal ready state.
Combat AHIT_P, RHIT_P, ADESTROY_P, RDESTROY_P Ask hit and destruction questions, then relay deterministic responses.
Turn State AVIC_P, RVIC_P, TURN_P Check victory or loss state and hand control to the opponent.
Radar ARADAR_P, RRADAR_P Ask and answer radar information for targeted board positions.

Build and Smoke Test

The preferred setup is Windows with Qt 6 MinGW 64-bit. The helper scripts keep the Qt path explicit so configure, build, run, and packaged-run behavior remains repeatable.

.\scripts\run.ps1 -QtDir $env:QT_DIR
.\scripts\run-packaged.ps1

Known Constraints

i

Project Boundaries

The project is designed around Qt Widgets rather than QML. Most UI state is coordinated by one large MainWindow, and online play uses a lightweight relay server rather than a secure authoritative backend.
