Flight Deal Finder

I built Flight Deal Finder to plan trips the way I actually decide: pick a date window, set a trip length, then see the cheapest round trips first. It is a privacy-first local desktop app that searches cached prices from Amadeus and Travelpayouts and drops you into Google Flights or Booking with dates already filled.

Overview

Flight Deal Finder is a local desktop application built with Python and NiceGUI. It searches cached flight price data from multiple providers, ranks round-trip options by total price, and provides direct links to booking tools with the dates already filled. It runs 100% locally with no tracking and is meant for inspiration rather than final booking.

💡 Idea

Flip the usual destination-first approach. Start with a date window and trip length, then rank every valid round trip by total price.


Allows the user to explore the cheapest options inside their available time, rather than hunting for specific destinations.

⚠️ Problem

Exploring cheap trips inside a flexible window meant juggling tabs or manually testing every date pair. The tools were powerful, but not built for this flow.

  • Too many filters for quick inspiration
  • Hard to compare date windows fast
  • No clear "short trip" view
✅ Solution

The app runs locally, uses cached prices, and generates all valid depart/return pairs in the window. Results are sorted cheapest-first with direct booking links.

  • Search window + trip length constraints
  • Generate valid date pairs and sort by total price
  • Direct booking links for quick planning

How the search works

A fast, constraint-first pipeline that keeps results deterministic, searchable, and easy to compare.

  1. Validate inputs and date constraints, then reset the cancel_flag.
  2. Expand destinations and generate valid depart/return pairs inside the window.
  3. Send the search to AmadeusClient with progress callbacks updating the UI.
  4. On API/auth failures, fall back to TravelpayoutsClient.
  5. Cache responses in flight_cache.db (6-hour TTL) and build FlightDeal objects.
  6. Paginate results (10 per page) and render cards with Google Flights / Booking.com links.
ℹ

Search Window vs. Trip Duration

The search window defines when departures can happen. Trip duration defines how long the vacation lasts. They are independent inputs, so a 30-day window can still search for 3-7 day trips.

Architecture Overview

This Flight Deal Finder application follows a multi-tier architecture with a local NiceGUI presentation layer, a central controller, data access + caching, and a dual-provider API layer, supported by configuration and link generation.

Presentation, controller, data access, providers, and links form a clean local loop.

💻

Presentation Layer

NiceGUI serves a local web UI on port 8080 with a theme persisted in localStorage.

🧠

Business Logic

FlightSearchApp owns validation, pagination, progress updates, and lifecycle state.

🗃

Data Access

Airports load via airports.py from airports.json, plus a SQLite cache (flight_cache.db) with a 6-hour TTL.

📦

API Providers

AmadeusClient is primary, with TravelpayoutsClient used on API errors via search_deals().

🔑

Configuration

config.env + config.py manage credentials, OAuth2, and provider selection.

🔗

Link Generation

Google Flights and Booking.com URLs are encoded with dates + cities and open in new tabs.

Limitations & Notes

⚠

Cached data awareness

This app is built for inspiration, not final booking. Results come from cached provider data, so the latest fares may differ when you open the booking site.

ℹ

Window size matters

Month-long searches are powerful but broad. If you already have a target week, a narrower window will give clearer comparisons and faster results.

⏳

Large searches take longer

Worldwide + long windows can take more time. Start small, then expand if needed.

🧭

Use constraints to guide discovery

A tight date window or shorter trip length usually surfaces better "quick trip" options.

✅

Always verify on booking sites

Pricing can shift quickly, so treat results as a shortlist and confirm before booking.
