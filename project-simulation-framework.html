Abstract

The dissertation presents a simulation framework created to evaluate human-machine collaboration strategies in industrial assembly lines. It was designed to reproduce discrete-event production environments using real operational data from Bosch Security Systems, S.A.

Two assembly lines were modeled as case studies, multiple scenarios were tested, key indicators such as throughput, utilization, value-added time, and cycle time were extracted, and a cost-benefit analysis was used to judge whether a cobot-based improvement made industrial sense.

Chapter 1 - Introduction

The first chapter frames the dissertation around a real industrial problem: how to allocate tasks between people, machines, and collaborative robots in a way that improves output without sacrificing flexibility, usability, or decision quality.

C Context and Motivation

Bosch Ovar operates a large manufacturing environment where many assembly lines run in parallel. In that setting, balancing human flexibility with machine consistency is a real optimization challenge.

  • Humans adapt well to variability and exceptions
  • Machines and cobots excel at repetitive and demanding work
  • A better mix can improve productivity and working conditions
P Problem Statement

Existing simulation tools were too generic, too closed, or too cumbersome for rapid what-if analysis in a Bosch-like environment. Engineers needed a modular and practical decision-support tool they could use without rebuilding a whole model from scratch.

  • Too much complexity for quick industrial testing
  • Limited transparency in proprietary logic
  • Weak support for hybrid human-machine-cobot lines
O Main Objective

Develop a simulation-based decision-support framework that can model real assembly lines, validate them against factory data, compare alternative layouts, and support investment decisions around automation and cobots.

  • Model real Bosch process flow and timing
  • Run scenario-based evaluation
  • Link operational gains to financial impact

Research Approach and Methodology

  1. Review literature on Industry 4.0, human-robot collaboration, digital twins, and simulation technologies.
  2. Develop a custom simulation framework tailored to hybrid assembly-line decision support.
  3. Collect Bosch data through observations, process documentation, and engineer feedback.
  4. Build and test baseline and improved scenarios using the same framework.
  5. Validate the models by comparing simulated output with real production indicators.
  6. Interpret the results in terms of bottlenecks, workload balance, and cost-benefit tradeoffs.

Chapter 3 - Development of the Simulation Framework

This chapter explains how the framework itself was designed and built. The aim was not only to create a simulation engine, but to create a framework that an engineer could actually use to construct, validate, run, and compare scenarios in a visual way.

Goals and Design Principles

MOD

Modularity

Separate logic, interface, logging, and statistics so the framework can evolve cleanly.

VIS

Visual Construction

Let users build assembly lines graphically instead of forcing code-first model creation.

VAL

Validation

Check structural logic before runtime so incorrect models are caught early.

OSS

Open Foundation

Retain full control over model behavior without license restrictions or hidden logic.

CFG

Configurability

Make it easy to change operators, timings, buffers, routing, and cobot behavior.

Selected Toolchain

PY

Python

Chosen as the common language for the interface, logic, and analysis layers.

DES

SimPy

Used as the discrete-event core for processes, resources, queues, and scheduling.

QT

PyQt5

Used to create the graphical interface for model construction and parameter editing.

XLS

Excel-Oriented Data Flow

Supports process-time import, log export, and easy post-run analysis in familiar tools.

Implementation Highlights

Graphical User Interface

The Qt-based interface includes the main window, file controls, a canvas, an element palette, add/edit dialogs, validation feedback, and runtime parameters for each scenario.

KP

Output Metrics and Logging

The framework records piece logs and operator logs, then derives metrics such as throughput, station cycle time, hold time, rejection rates, and economic return.

LM

Known Limitations

Operator behavior is simplified, cobot behavior is modeled rather than fully validated, ergonomic aspects are not simulated, and the framework is not yet a live digital twin.

L05B/V2 Solution

Cobot Integration Paid Off

The improved solution automated the sensitivity test, welding, and standby test sequence and also reassigned soldering responsibility to balance operator workload.

  • 3085 completed pieces in 25 hours
  • Extra 484 pieces in equal working time
  • Estimated payback time of 73.26 working days
ROI

Main takeaway

The strongest result of the dissertation is not only the improved scenario itself, but the fact that the improvement can be justified with data before touching the real line. The framework turns layout and automation discussions into measurable decisions.

Chapter 6 - Conclusions and Future Work

The final chapter reflects on what the framework achieved, where it still falls short, and how it could evolve from a proof-of-concept decision-support system into a stronger planning and digital-twin foundation.

Critical Assessment of the Framework

AG

Configurational Agility

Alternative layouts and task reallocations can be instantiated quickly, which is a major practical strength for scenario testing.

EF

Computational Efficiency

The discrete-event approach compresses long periods of physical production into fast computational experiments.

TR

Analytical Transparency

Detailed logs make the simulation inspectable, but built-in visualization and reporting are still limited.

LM

Current Limits

Ergonomics, operator fatigue, richer buffer logic, and live factory synchronization are not yet part of the framework.

OBJ

Alignment with the dissertation objectives

According to the dissertation, all core objectives were addressed except the final step of producing more detailed optimization recommendations for the current Bosch processes. Time constraints limited that final layer, but the framework and results now provide the basis needed for it.

Future Work

1

Broadened resource modeling

Add more machine types, richer buffer behavior, more cobot profiles, and ergonomic factors.

2

Automated analytics

Generate dashboards, utilization heatmaps, and better built-in reporting directly from each run.

3

Empirical expansion

Validate more use cases, more lines, and more production contexts to strengthen reliability.

4

Pathway to a digital twin

Connect the framework to live production data and ongoing calibration for real-time decision support.
